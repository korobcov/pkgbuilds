# 1c-enterprise-thin-client

Тонкий клиент **1С:Предприятие 8.3** для Arch Linux / CachyOS, собранный из официального `.deb`-пакета.

## Где взять .deb

Сам дистрибутив в репозиторий не входит: его распространение ограничено лицензией 1С. Варианты:

- скачать на [releases.1c.ru](https://releases.1c.ru) — «Клиент 1С:Предприятия для DEB-based Linux-систем, 64-бит»;
- попросить у администратора 1С вашей организации (версия должна совпадать с версией сервера).

Нужен только основной пакет `1c-enterprise-<версия>-thin-client_<версия>_amd64.deb`.
Пакет `-nls` содержит дополнительные языки интерфейса; русский и английский уже есть в основном.

## Сборка и установка

```sh
git clone https://github.com/korobcov/pkgbuilds
cd pkgbuilds/1c-enterprise-thin-client
cp ~/Загрузки/1c-enterprise-8.3.27.1859-thin-client_8.3.27-1859_amd64.deb .
makepkg -si
```

Для другой версии платформы поменяйте в `PKGBUILD` переменные `pkgver` (`8.3.27.1859`) и `_debver` (`8.3.27-1859`).

## Что делает пакет

Повторяет `postinst` из официального `.deb`:

- переключает webkit-расширение и wxWidgets на сборки под **webkit2gtk-4.1** (файлы `*.wk41`) — сам `postinst` делает это только для Ubuntu > 23, Astra и Mint;
- создаёт `/opt/1cv8/conf/conf.cfg` с русским языком интерфейса;
- кладёт программу запуска `1cestart` и её библиотеки в `/opt/1cv8/common`;
- удаляет бандленную `libstdc++` (используется системная).

Дополнительно для Arch:

- удаляет бандленную `libgcc_s` — она старее, чем нужно системным библиотекам (`GCC_12.0.0 not found`);
- `/usr/bin/1cv8c`, `1cv8s`, `1cestart` — скрипты-обёртки с `LD_PRELOAD=/usr/lib/libstdc++.so.6` (см. ниже);
- в меню приложений остаётся один ярлык «1С:Предприятие» (`1cestart`), дубли `1cv8c`/`1cv8s` скрыты.

Зависимости взяты из официального `v8-install-deps.sh` и переведены на пакеты Arch.

## Почему нужен LD_PRELOAD

Симптом: клиент сразу падает с

```
LLVM ERROR: out of memory
Buffer allocation failed
```

Причина не в памяти и не в видеодрайвере. Библиотека 1С `wbase.so` экспортирует собственный
`operator new(size_t, std::align_val_t, const std::nothrow_t&)`. Когда Mesa загружает `libLLVM`
(через `libgallium`, при создании GL-контекста), LLVM связывается с этой реализацией, получает `NULL`
и аварийно завершается в `llvm::allocate_buffer`. Замечено на Mesa 26 / LLVM 23.

Проверить, кому достаётся символ:

```sh
LD_DEBUG=bindings /opt/1cv8/x86_64/8.3.27.1859/1cv8c 2>&1 | grep align_val_t | grep libLLVM
```

С системной `libstdc++` в `LD_PRELOAD` LLVM получает стандартный `operator new`, и клиент запускается.

## Подключение базы

- **База, опубликованная на веб-сервере:** «1С:Предприятие» → *Добавить* → *Добавление в список существующей информационной базы* → тип расположения *На веб-сервере* → адрес публикации.
- **Вход без ввода пароля:** в свойствах базы, поле *Дополнительные параметры запуска*: `/N"логин" /P"пароль"`.
  Пароль хранится открытым текстом в `~/.1C/1cestart/ibases.v8i`.
- **Ярлык сразу на базу:** `1cestart ENTERPRISE /IBNameИмяБазы`.

## Удаление

```sh
sudo pacman -R 1c-enterprise-thin-client
```

Пользовательские настройки и кэш 1С остаются в `~/.1C` и `~/.1cv8`.
